# Вход в админку и пользователи

Ветка: `test`

---

## 1. Что сделано

- **Вход по логину и паролю** — страница `/login`. Админка `/admin` закрыта: без входа перекидывает на форму.
- **Регистрация** — на той же странице, вкладка «Регистрация». После заявки письмо уходит на почту владельца (`antipenkoekaterina097@gmail.com`) со ссылкой подтверждения. До подтверждения вход не работает — показывается «Доступ ещё не подтверждён владельцем».
- **Раздел «Пользователи» в админке** — список всех пользователей со статусами, изменение имени, почты и пароля, подтверждение и закрытие доступа, удаление.
- **Добавление пользователя прямо из админки** — имя, почта, пароль. Такой пользователь сразу подтверждён, письмо не требуется.
- Пароли нигде не хранятся в открытом виде.

---

## 2. Как работает подтверждение

```
регистрация  →  статус pending  →  письмо владельцу со ссылкой
                                        ↓
                     клик по ссылке в письме  →  статус approved
                     или кнопка «Подтвердить доступ» в админке
                                        ↓
                              вход по логину и паролю работает
```

Подтвердить можно двумя способами — ссылкой из письма или вручную в разделе «Пользователи». Второй способ удобен, если письмо потерялось.

---

## 3. Два режима работы

Как и с проектами, код работает и без базы.

| Режим | Когда | Где живут пользователи | Пароли |
|---|---|---|---|
| Локальный | ключей Supabase нет | localStorage браузера | хеш SHA-256 |
| Боевой | ключи заданы | Supabase Auth + таблица `admin_users` | хранит Supabase (bcrypt) |

В локальном режиме **первый зарегистрированный пользователь подтверждается сразу** — это владелец. Все следующие проходят через подтверждение. Локальный режим нужен только для разработки: он живёт в одном браузере и защищает от случайного клика, а не от взлома.

## 4. Таблица `admin_users`

```
id              uuid → auth.users.id (каскадное удаление)
name            text
email           text, уникальный
status          pending | approved | rejected
approval_token  text   → одноразовый код из письма
created_at      timestamptz
```

Права в базе (RLS) построены на функции `is_approved_admin()`: писать проекты, картинки и ссылки может только пользователь со статусом `approved`. Поэтому даже если кто-то войдёт неподтверждённым, изменить в базе он ничего не сможет.

---

## 5. Серверные функции (Supabase Edge Functions, бесплатно)

Лежат в `supabase/functions/`. Нужны потому, что создание чужого пароля требует служебного ключа, который нельзя держать в коде сайта.

| Функция | Что делает |
|---|---|
| `admin-signup` | после регистрации создаёт запись со статусом `pending`, генерирует код и отправляет письмо владельцу |
| `approve-admin` | открывается по ссылке из письма, ставит статус `approved` |
| `manage-admin-user` | создание, изменение (имя, почта, пароль, статус) и удаление пользователей из админки |

Каждая проверяет, что вызывающий — подтверждённый администратор.

### Развёртывание

```bash
npx supabase login
npx supabase link --project-ref ВАШ_REF
npx supabase functions deploy admin-signup approve-admin manage-admin-user
```

Секреты для функций (задаются один раз):

```bash
npx supabase secrets set WEB3FORMS_KEY=ключ OWNER_EMAIL=antipenkoekaterina097@gmail.com
```

`SUPABASE_URL`, `SUPABASE_ANON_KEY` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам.

## 6. Первый вход на боевом сервере

1. Выполнить `supabase/schema.sql` в SQL Editor.
2. Создать себе пользователя: **Authentication → Users → Add user** (почта и пароль).
3. Выполнить в SQL Editor, подставив свой id из списка пользователей:

   ```sql
   insert into admin_users (id, name, email, status)
   values ('ваш-uuid', 'Екатерина', 'antipenkoekaterina097@gmail.com', 'approved');
   ```

4. Войти на `/login`. Дальше остальных пользователей можно добавлять прямо из админки.

## 8. Проверено вживую

- `/admin` без входа перекидывает на `/login`;
- регистрация первого пользователя выдаёт доступ владельцу, пароль сохраняется хешем;
- неверный пароль не пускает, верный — открывает админку;
- заявка второго пользователя получает статус `pending`, вход блокируется;
- после кнопки «Подтвердить доступ» тот же логин и пароль пускают в админку;
- добавление пользователя из админки работает;
- смена имени, почты и пароля сохраняется, пароль в открытом виде не хранится;
- `yarn build` и `yarn lint` — без ошибок.

---

## 9. Что стоит сделать перед публикацией

- Развернуть три функции и задать секреты (раздел 5) — до этого письмо-подтверждение уходит только в локальном виде.
- Включить в Supabase ограничение на попытки входа (Authentication → Rate limits).
- По желанию — сброс пароля по почте: `supabase.auth.resetPasswordForEmail`.
