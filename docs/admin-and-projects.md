# Проекты, внутренние страницы и админка

Ветка: `test`

---

## 1. Что сделано

- **У каждой картинки в орбите свой индекс.** Порядковый номер виден на бейдже и лежит в `data-index`, идентификатор проекта — в `data-id`. По клику наружу отдаётся `onSelect(id, index)`.
- **Клик по картинке ведёт на страницу проекта** — `/project/:id`, где `id` это slug проекта (можно открыть и по числовому id).
- **Внутренняя страница проекта** — слева вертикальная лента изображений (как презентация на Behance), справа закреплённая колонка: заголовок, теги, описание, выпадающий список с пунктами-ссылками.
- **Админка** — `/admin`: список проектов, редактирование полей, добавление и удаление проектов, картинок и пунктов списка, изменение порядка стрелками.
- **Слой данных** — единый API (`src/lib/projectsApi.ts`) с двумя режимами: Supabase (когда заданы ключи) и localStorage (пока ключей нет). Компоненты не знают, откуда данные.
- **Схема БД** — `supabase/schema.sql`.

## 2. Бесплатный стек

| Слой | Сервис | Бесплатный лимит |
|---|---|---|
| База данных (Postgres) | Supabase | 500 МБ, 2 проекта, без карты |
| Хранилище картинок | Supabase Storage | 1 ГБ |
| Вход в админку | Supabase Auth | до 50 000 пользователей |
| Хостинг сайта и поддомена | Vercel или Netlify | статика без лимита запросов |
| Заявки с формы | Web3Forms | 250 писем в месяц |

Отдельный сервер не нужен: Supabase сам поднимает REST-API поверх Postgres, фронтенд ходит в базу напрямую. Запись закрыта политиками RLS — читать может любой, писать только авторизованный владелец.

Поддомен для админки (например `admin.домен.ру`) настраивается в панели хостинга как отдельный проект или как алиас основного — код один и тот же, отличается только маршрут.

## 3. Структура базы

```
projects
  id           uuid, первичный ключ   → попадает в ссылку
  slug         text, уникальный       → человекочитаемый адрес: /project/branding
  title        text
  description  text
  tags         text[]
  cover_url    text                   → картинка в орбите на главной
  sort_order   int                    → порядок вывода
  created_at   timestamptz

project_images                        → лента изображений слева
  id, project_id → projects.id (каскадное удаление)
  url, caption, sort_order

project_links                         → пункты выпадающего списка справа
  id, project_id → projects.id (каскадное удаление)
  label, url, sort_order
```

## 4. Подключение базы (когда будет хостинг)

1. Завести проект на https://supabase.com (бесплатный план).
2. В разделе **SQL Editor** выполнить файл `supabase/schema.sql` — создадутся таблицы и политики доступа.
3. В **Project Settings → API** скопировать `Project URL` и `anon public key`.
4. Добавить в `.env` (шаблон — `.env.example`):

   ```
   VITE_SUPABASE_URL=https://ваш-проект.supabase.co
   VITE_SUPABASE_ANON_KEY=ваш_anon_ключ
   ```

5. Перезапустить проект. Дальше сайт и админка работают с базой, localStorage больше не используется.

На хостинге те же две переменные задаются в настройках проекта (Environment Variables).

### Картинки

Файлы загружаются в **Supabase Storage** (бакет `projects`, публичный доступ на чтение), в админку вставляется публичная ссылка на файл. Пока бакета нет — подойдёт любая прямая ссылка на изображение.

### Защита админки

Пока `/admin` открыт всем — на локальной разработке это удобно. Перед публикацией нужно включить вход: в Supabase создать пользователя (Authentication → Users), а в админке добавить форму входа через `supabase.auth.signInWithPassword`. Политики RLS уже написаны так, что записывать может только авторизованный, поэтому даже при открытой странице чужой человек ничего не сохранит в базу.

## 5. Маршруты

| Адрес | Страница |
|---|---|
| `/` | Главная с орбитой проектов |
| `/project/:id` | Внутренняя страница проекта |
| `/admin` | Админка |

Для корректной работы прямых ссылок на статик-хостинге добавлены `public/_redirects` (Netlify) и `vercel.json` (Vercel) — любой адрес отдаёт `index.html`.

## 6. Структура добавленных файлов

```
src/
  types/project.ts              # типы Project, ProjectImage, ProjectLink
  lib/
    supabase.ts                 # клиент Supabase (null, если ключей нет)
    projectsApi.ts              # чтение и запись: Supabase или localStorage
  data/seedProjects.ts          # стартовые проекты и раскладка орбиты
  pages/
    HomePage.tsx                # главная: орбита из проектов БД
    ProjectPage.tsx / .styles   # внутренняя страница проекта
    AdminPage.tsx / .styles     # админка
supabase/schema.sql             # таблицы и политики доступа
```
