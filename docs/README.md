# Документация: навигация и форма «Обсудить проект»

Ветка: `test`

Здесь описано, что добавлено в проект, как это устроено и как настроить приём заявок с формы на почту после публикации на хостинге.

---

## 1. Что сделано

- **Шапка сайта (навигация)** — блок `B-header`: строка пилюль-ссылок (`Обо мне`, `Стек`, `Резюме`, `Опыт`, `Инспо`) слева и белая кнопка **«Обсудить проект»** справа. Сделано по макету: тёмный фон, скруглённые пилюли, белая кнопка со стрелкой ↗.
- **Модальное окно с формой** — блок `B-project-modal`: открывается по кнопке «Обсудить проект». Поля: **Имя**, **Почта**, **Телефон**. Закрывается по крестику, клику вне окна и клавише `Esc`; во время открытия блокируется прокрутка страницы.
- **Отправка заявок на почту** — форма шлёт данные через сервис **Web3Forms** (бесплатно, без бэкенда). После настройки ключа заявки будут приходить на почту-получатель.
- **Главная страница** (`App.tsx`) — тёмный фон с лёгкой текстурой, шапка сверху, простой герой-блок с именем.
- **Исправлен `vite.config.ts`** — из-за неверного порядка плагинов React-компилятор ломал хуки (см. раздел 5).

## 4. Приём заявок на почту (бесплатно)

Сайт статический (Vite + React) — своего сервера нет, поэтому отправку письма берёт на себя сторонний бесплатный сервис. Выбран **Web3Forms**: бесплатный тариф — 250 заявок в месяц, без регистрации сложных бэкендов, работает на любом статик-хостинге (GitHub Pages, Netlify, Vercel, Cloudflare Pages).

### Как это работает

Форма отправляет `fetch`-запрос на `https://api.web3forms.com/submit` с «ключом доступа». Ключ привязан к вашей почте — Web3Forms пересылает каждую заявку на неё. Сама почта в коде сайта не светится (в отличие от прямого `mailto`), спам-защита — на стороне сервиса.

### Настройка (один раз, перед публикацией)

1. Зайдите на https://web3forms.com, введите почту-получатель (например, `v.starrett.mzpo@gmail.com`) и получите **Access Key** (придёт на почту / покажется на странице).
2. Создайте файл `.env` в корне проекта (рядом с `package.json`) на основе `.env.example`:

   ```
   VITE_WEB3FORMS_KEY=сюда_вставить_ключ
   ```

3. Пересоберите/перезапустите проект. Ключ подхватывается в `src/config.ts`.

На хостинге ключ задаётся так же — переменной окружения `VITE_WEB3FORMS_KEY` в настройках проекта (Netlify/Vercel/Cloudflare) либо через `.env` при сборке. Первая заявка активирует адрес (Web3Forms пришлёт письмо-подтверждение).

> Пока ключ не задан, форма работает, но при отправке покажет ошибку «Не удалось отправить» — это ожидаемо до настройки.

### Бесплатные альтернативы (если Web3Forms не подойдёт)

- **FormSubmit.co** — вообще без регистрации: форма шлёт на `https://formsubmit.co/ВАША_ПОЧТА`. Минус — почта видна в исходниках (можно скрыть их хешем из личного кабинета).
- **Formspree** — бесплатный тариф 50 заявок/мес, удобная панель.
- **EmailJS** — бесплатно 200 писем/мес, отправка прямо из браузера.

Чтобы поменять сервис — правится только один запрос в `src/components/blocks/B-project-modal/B-project-modal.tsx` (функция `submit`).

## 5. Правка `vite.config.ts` (важно)

В исходном конфиге React-компилятор подключался babel-плагином **после** `react()`:

```ts
plugins: [ react(), babel({ presets: [reactCompilerPreset()] }) ]
```

При таком порядке компилятор обрабатывал уже трансформированный код (с обёртками react-refresh) и ломал диспетчер хуков — в консоли сыпалось `Invalid hook call` / `Cannot read properties of null (reading 'useContext')`, styled-components падал. Пока страница была пустой, ошибка не проявлялась.

Компилятор должен идти **первым**, по исходному коду. Исправлено на:

```ts
plugins: [ babel({ presets: [reactCompilerPreset()] }), react() ]
```

После правки консоль чистая, сборка и dev работают.
